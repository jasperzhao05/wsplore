## Design

**Strategy.** Move the paddle to the column where the ball will land, wait there with no-op, and catch it. The paddle moves at the ball's horizontal speed, so it needs as much warning as possible.

To make the prediction simple, I unfold the horizontal motion. Use a coordinate u (mod 20) that grows by 1 every step. The real column is fold(u): u for u ≤ 9, and 19−u otherwise. This automatically handles the extra "stay" step at a wall.

**Descending ball at row y.** It reaches row 8 at u8 = u + 8 − y.

**Ascending ball.** It assumes the earliest possible bounce:
- If y ≥ 4, it assumes a brick in row 3, so u8 = u + y + 1. This value stays constant while the ball climbs.
- If y < 4, it assumes a brick (or the top wall) just above, so u8 = u + 9 − y.
- If the ball keeps climbing, the prediction moves by 2 per row. The ball also takes 2 more steps per row, so the paddle keeps its time margin.

Across all catch geometries, the worst-case slack is at least 1 step.

**Which catch column to aim for.**
- **Early:** aim for x8 = fold(u8), the straight-hit column, which keeps the horizontal direction. With straight hits, the parity of the catch position is preserved and the ball sweeps every column of every brick row. So the ball cannot loop forever without breaking bricks.
- **Final step** (ball on row 8, moving down): accept either valid column, fold(u8) or fold(u8+1).

**Layer 1.**
- **Units 0–7: landing errors for the four directions** (down-right, down-left, up-right, up-left), with two threshold units per direction:
  - R_d = tanh(6·(lo_d(ball cell) − paddle − 0.5)), meaning "the paddle must go right".
  - L_d = tanh(6·(paddle − hi_d(ball cell) − 0.5)), meaning "the paddle must go left".
  - lo and hi are per-cell lookup tables of the landing interval, which is exactly linear for a one-hot ball.
- **Unit 8: H (moving right).** It computes 6·(ball column − trail column ± 0.5 at the walls). This correctly decodes the wall-bounce frames, where ball column equals trail column.
- **Unit 9: V (moving up).** It computes 6·(trail row − ball row + 0.5 if ball row ≥ 5, −0.5 otherwise). This decodes the bounce frames: a paddle catch means up; a brick or top-wall bounce means down.

**Layer 2.** It gates each error unit by direction: unit j = tanh(5·(err_j ± H ± V − 2)). A unit fires only if its own direction matches and a move is needed.

**Output.**
- Right logit = 10·Σ(right gates) + 30, which gives +10 when needed and −10 otherwise. Left is built the same way.
- No-op logit = 0.
- Up, down and fire get −30.
